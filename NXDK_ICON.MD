# Adding a Retail-Style Game Icon to an NXDK XBE

This process was validated with Perfect Dark X and CXBX-Reloaded on August 28,
2026. CXBX-R displayed the square Perfect Dark X icon in the lower-right corner
of its pre-launch screen.

## Important distinction

NXDK's `cxbe -LOGO` option does **not** set the square game icon. It replaces the
small monochrome 100 x 17 bitmap stored in the normal XBE header—the `nxdk` or
Microsoft-style wordmark shown during startup.

The retail-style square game icon is an Xbox Packed Resource (`XPR0`) embedded
in an inserted-file XBE section named `$$XTIMAGE`. The Microsoft XDK's
`imagebld.exe` normally adds this with `/TITLEIMAGE`. NXDK's stock `cxbe` has no
equivalent option; its supported metadata options are limited to items such as
`-TITLE`, `-MODE`, `-LOGO`, and `-DEBUGPATH`.

Perfect Dark X keeps the NXDK linker and `cxbe`, then adds the retail dashboard
sections in a post-link step.

## Required assets

The project uses these files:

- `TitleInfo.txt`: ASCII text containing the dashboard title.
- `TitleImage.xbx`: 128 x 128 square title icon packed as a 10,240-byte `XPR0`
  resource.
- `SaveImage.xbx`: 64 x 64 square save icon packed as a 4,096-byte `XPR0`
  resource.

Example `TitleInfo.txt`:

```ini
[default]
TitleName=Perfect Dark
```

In this repository they live in `port/xbox_assets/`.

### Generating the XPR files

`tools/xbox_assets/build_dashboard_assets.py` converts a square source icon to
128 x 128 and 64 x 64 BMP images, then invokes the Xbox resource bundler to
produce single-level DXT1 `XPR0` resources:

```powershell
python tools/xbox_assets/build_dashboard_assets.py `
  --icon "Perfect Dark X.ico" `
  --out port/xbox_assets `
  --bundler "C:\XDK_5558\XDK\xbox\bin\bundler.exe"
```

The generator requires Pillow and Microsoft's `bundler.exe`. The finished
`.xbx` assets can be retained and reused by ordinary NXDK builds; the XDK is not
needed to link or insert them afterward.

## Inserting the resources into an NXDK XBE

After `cxbe` creates `default.xbe`, run:

```powershell
python scripts/insert-xbe-dashboard-assets.py `
  --xbe build-xbox/default.xbe `
  --title-info port/xbox_assets/TitleInfo.txt `
  --title-image port/xbox_assets/TitleImage.xbx `
  --save-image port/xbox_assets/SaveImage.xbx
```

The script adds the same retail-style inserted-file sections produced by the
XDK image builder:

| Section | Contents | Expected size |
| --- | --- | ---: |
| `$$XTINFO` | ASCII title information | Variable |
| `$$XTIMAGE` | 128 x 128 title icon (`XPR0`) | 10,240 bytes |
| `$$XSIMAGE` | 64 x 64 save icon (`XPR0`) | 4,096 bytes |

The inserter:

1. Preserves the executable sections generated by `cxbe`.
2. Relocates the XBE section-header table into unused header space.
3. Appends the three resources on page-aligned file offsets.
4. Creates inserted-file section headers with flags `0x38`.
5. Calculates and stores the SHA-1 digest for each new section.
6. Updates the XBE header size, image size, section count, and table pointer.

This avoids passing an NXDK-linked PE through `imagebld.exe`. In testing,
`imagebld.exe` rejected NXDK's normal fixed-address PE because it has no base
relocations. Relinking with `/FIXED:NO` worked experimentally, but unnecessarily
changed the already validated NXDK executable and introduced an XDK build-time
dependency.

## CMake integration

Run the inserter as a `POST_BUILD` command immediately after `cxbe` and any XBE
header metadata patching:

```cmake
add_custom_command(TARGET game POST_BUILD
  COMMAND ${CXBE_EXECUTABLE}
    -OUT:${CMAKE_BINARY_DIR}/default.xbe
    -TITLE:"Game Title"
    $<TARGET_FILE:game>
  COMMAND ${Python3_EXECUTABLE}
    ${CMAKE_SOURCE_DIR}/scripts/insert-xbe-dashboard-assets.py
    --xbe ${CMAKE_BINARY_DIR}/default.xbe
    --title-info ${CMAKE_SOURCE_DIR}/port/xbox_assets/TitleInfo.txt
    --title-image ${CMAKE_SOURCE_DIR}/port/xbox_assets/TitleImage.xbx
    --save-image ${CMAKE_SOURCE_DIR}/port/xbox_assets/SaveImage.xbx
)
```

If another post-build command rewrites or regenerates the XBE, perform that
operation before resource insertion. Do not run the inserter twice on the same
XBE.

## Verification

Before testing, confirm that the resulting XBE has the inserted sections and
that both image resources begin with `XPR0`. Perfect Dark X's validated build
had seven sections total: its four executable sections plus `$$XTINFO`,
`$$XTIMAGE`, and `$$XSIMAGE`.

Then open the resulting `default.xbe` directly in CXBX-Reloaded. The square
`$$XTIMAGE` artwork should appear in the lower-right corner of the pre-launch
screen. Reopen the XBE if CXBX-R has cached metadata from an earlier build.

Loose `TitleImage.xbx` and `SaveImage.xbx` files may still be useful to custom
dashboards or installers, but they did not replace the need for the embedded
`$$XTIMAGE` section in CXBX-R's pre-launch display.
